## Algorithm and metrics

Standard stable, shift-based Insertion Sort: lift the next key, compare values
in the ordered prefix, shift larger values right, and reinsert the key into the
gap. Strict `left > key` preserves the original ordering of equal values.

Primary reference checked: [Princeton's official InsertionX.java source](https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/InsertionX.java).
The Princeton site returned HTTP 403 through browsing, so its official GitHub
source was used. The code here is an original, ordinary insertion implementation;
it does **not** use InsertionX's initial sentinel/exchange optimization. Only
its shift/key-placement semantics and complexity/stability documentation informed
the explanation; no reference animation/code was copied into this scene.

- `comparisons`: one comparison of a prefix value with the held key. Index-boundary
  checks are excluded.
- `shifts`: one existing value moved one slot right.
- `placements`: one reinsertion of the held key, including a return to its original
  position; exactly n−1. If total array writes are wanted, shifts+placements.
- No operation is mislabeled as a swap.

| Input | Output | Comparisons | Shifts | Placements |
|---|---|---:|---:|---:|
| [5,2,4,1,3] | [1,2,3,4,5] | 9 | 7 | 4 |
| [8,3,7,2,6] | [2,3,6,7,8] | 9 | 7 | 4 |
| [4,1,6,2,5,3] tutorial | [1,2,3,4,5,6] | 11 | 7 | 5 |

Fixed worker keys are `insertion_custom` and `insertion_tutorial`. Renderer
version is `arena-v3-insertion`; old Bubble keys remain `custom` and `tutorial`.
`insertion_trace()` returns immutable events plus initial/final/metrics and
serializable `to_dict()`. Tests replay the held-key/gap/shift events independently,
track original element identities to prove stability, check each ordered prefix,
and compare 500 seeded arrays against `sorted()`. Shift count is also checked
against inversion count. The ordinary sorted best case has n−1 comparisons and
zero shifts; reversed worst case has n(n−1)/2 comparisons and shifts.

Original 16:9 design reuses `Tile`, `cmr`, `math`, palette, focus halos and final

## Real issue found and corrected

The first prototype used simultaneous animation of the key VGroup and its child
box. Manim moved the label while the box's separate transform conflicted, visibly
separating values and boxes. **Prototype visual FAIL** is retained as
`prototype-shift.png` and `prototype-metadata.json`;
`renderer/renders/insertion/custom1.mp4` is the failed prototype, not a release
asset. The correction styles the key box before moving its whole VGroup.
Fresh release renders above show value/box identity intact at lift, shift and
completion. A first build also caught a missing Scene import and was corrected
before successful rendering. These failures are observed evidence, not seeded.
